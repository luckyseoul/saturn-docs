1. Basic items (common items for all input peripherals)

1) Compatible input peripheral setting principles

Regarding input peripherals (compatible P) that can be used in applications, please refer to the "Software Creation Standards".〈 Pad setting principles〉 The following principles must be adhered to.

＜ Supported input peripheral setting principles＞

- Do not start the game if compatible P is not connected to terminal 1 of the main unit.

- In principle, main body terminal 1 corresponds to 1P operation, and main body terminal 2 corresponds to 2P operation.

2) Check input peripherals

As a general rule, check as often as possible while the power is on, and at least take measures to prevent runaways .
Please refer to the recommended specifications below for information on when and what kind of checks should be performed.

《Recommended specifications》

(a) Check before starting

◆Checking compatible P (registering valid terminals)

  • Check whether the connected peripheral is compatible with P. The terminal to which the corresponding P is connected is set as the valid terminal .
  • For unsupported Ps, it is assumed that they are not connected , or a warning is displayed to request the user to replace them.
  • The above checks are performed not only at the timing of the [pad check] after the power is turned on, but also as frequently as possible within the [title loop].

    *Especially in applications that do not support mice, be careful not to cause unstable operation when a mouse is connected.

    *In multiplayer games where each player has a different start time (you can join in the middle), check frequently at all times, including during the main game.

(b) Check at start

◆Starting the application

  • As a general rule, the start of play shall be performed by 1P (corresponding to P of main body terminal 1) .
  • As a general rule, 1P is responsible for selecting modes and setting options during the game .

    *In multiplayer games where mid-game participation is possible, it may be possible to start from a point other than 1P.

    *In a multiplayer game, each player may be allowed to set the settings individually.

◆Determining the terminal to be used

  • At the start, the terminal to be used in the game is determined from among the valid terminals .

    *Terminals used by more than the maximum number of players will not be selected.

(c) Check in main game

◆Checking for insertion and removal

  • Removal/insertion (or addition) of input peripherals during the [main game] must be handled in such a way that no problems occur, regardless of intentional negligence on the part of the user .

(i) If unplugged

  • If the used P is removed during play, it is determined that there is no input . (or do a "system pause" and display a warning at the same time)
    →The terminal becomes a "vacant and used terminal".
  • If an unused P or an unsupported P is removed, it is ignored . (Do not unnecessarily hinder game progress)

＜ About “System Pause”＞

*"System Pause" is recommended in the following cases:
  • If the multi-terminal is unplugged while it is in use.
  • If no input is required, the game play will proceed in a direction that the user does not like.

    *The "system pause" can be canceled from any used P when the removed used P is returned (when the application determines that it can be used again).

    *If the user enters the "system pose" while in the user pose, the user pose will be automatically canceled when the "system pose" is canceled. (For example, if a peripheral is removed during user pose)

(ii) if it is posted;

  • Input is resumed only when the corresponding P is returned to the "vacant used terminal" . (If in pause state, wait for release)
  • Otherwise, it will not affect the game .

    *Even if a P other than the removed used P is returned, if it is a corresponding P, input is resumed.

(iii) if added;

  • In applications where [partial participation] is performed, a corresponding P may be additionally inserted into an invalid terminal. In this case, even if the [main game] is in progress, it may be used as a valid terminal or a used terminal.
  • In this case, be careful that the connection operation itself does not affect the game .

    *The terminal to be used will be re-determined at the following timing.

    1. At the start of the next game.
    2. Do this immediately after connecting. However, in this case, take measures such as requiring the user who joins the game to start the game by pressing the start button.

    *Terminals used by more than the maximum number of players will not be selected.

3) Support for optional items

When making an application compatible with each input peripheral, it must be possible to operate it using the CONTROL PAD, except in special cases. Therefore, at a minimum, the optional control settings (CONTROL) must correspond to both input peripherals (CONTROL PAD and each supported input peripheral). Observe the following rules when matching options to each input peripheral .

  • Add items that may be needed specific to each input peripheral
    → "Cursor speed" (cursor movement speed) in mouse, etc.
  • Automatically detects the connected input peripheral and displays the corresponding screen (item)
    →Be sure to check the pad (connection status) when entering the options screen.
    (It is also desirable to do this frequently on the options screen.)
  • All settings are memorized for each peripheral.

4) Regarding terms used in the game

If it is necessary to display the name of each input peripheral in the game, in principle, use the name used within this creation standard.

		Multi-terminal racing controller, shuttle mouse, etc.
