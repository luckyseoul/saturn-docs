サウンド開発ノウハウ集

第1章　基本概要

  • 「サウンドドライバVer.2.20プログラマーズガイド」はプログラマ向けの技術資料です。ぜひ一度、目を通してください。サウンド処理上の重要な情報が、説明されています。

  • 現在リリース直前というプロジェクト以外は、最新のサウンドドライバ（Ver.2.04以降）をかならず使用してください。データの互換性の問題から、それ以前のバージョンを使用せざるえない場合はバージョン1.33Bのみにかぎります。
    データ制作時とゲームに組み込む時の、ドライバのバージョンも合わせてください。
    使用しているサウンドドライバのバージョンは、ドライバの先頭から1020h以降を16進数でダンプすると、ASCIIコードで記述されています。
    SndSimlator上から判別するには、アップルメニューの「このSndSimlatorについて」を開いてください。

  • 思い通りにサウンドが動作しない、なにかトラブルが起こる場合に参照すべきものは、3つあります。

    1. コマンド履歴
    2. エラーステータスビット
    3. モード、ステータス等の他のサウンドWORK RAMの情報

    これらについての詳細は「サウンドドライバVer.2.20プログラマーズガイド」を参照してください。

  • サウンドトラブル時の提出物についてトラブルを、

    1. マックのツール上で再現できるトラブル
    2. ツール上では正常だが、ゲームに組み込むと発生するトラブル
    に大別しますと、1の場合のトラブル時の提出物は
    マック上の開発時データ一式

    1. サウンドシミュレータのマップファイル
    2. TONEエディタの音色ファイル（.binファイルもあれば）
    3. DSP Linkerの.YLIファイル（.EXBファイルもあれば）
    4. シーケンサの出力した、STANDARD MIDI FILE（Type1）
    5. 説明のドキュメント

    2の場合はA、B、C、D、Eにくわえて

    1. 現象を再現できるCDーROMとその再現方法の説明

    をいただきたいと思います。

  • SH2からのサウンドコントロールの3つの方法

    1. SBL（PCM、ADPCM再生ライブラリ含む）ライブラリの関数を使用
    2. SGLライブラリの関数を使用
    3. サウンドライブラリを使わないで直接コマンドエリアにコマンドを書く

  • 基本的にサウンドツールは、PowerMac, 68x00Macを問わず、Macintoshの機種の違いによって、動作に異常をきたすことはありません。サウンドツールのトラブルの最も大きな原因はSCSI関連によるものです。トラブルを極力回避するために、MacintoshとSound Box間は、最短で良質のSCSIケーブルで接続し、使用しないSCSI機器は接続しないようにしてください。また、CartDev.環境においてはMIDI信号とSCSI転送が同時に頻繁に行われるとフリーズしやすいので、なるべく避けてください。

  • SndSimulatorによってサウンドマップを転送し、サウンドドライバを起動した後でないとTONEエディタ、DSPリンカは動作しません。これは転送されたマップの音色BANK、DSPワークRAMの設定されたアドレスとサイズを参照してTONEエディタ、DSPリンカが機能しているためです。
    波形エディタはサウンドボックスのRAMをワークエリアとして使用しているだけですので、サウンドマップの転送や、サウンドドライバの起動は必要ありません。波形エディタ使用中はサウンドボックス背面の1から8までLEDのいくつかが点灯したままになりますが正常です。波形エディタはアドレス10000H以降をそのワークエリアとして使用し、破壊します。再度ToneエディタやDSPリンカを使用する場合は必要に応じてデータを転送し直してください。

  • サウンドシミュレータのPCMストリーム再生も、SCSIで転送してシミュレートしているため、実機と違う鳴り方をする可能性があります。この機能はあくまで簡易的なものと考えてください。

  • Sound Box(Sound Board System)においては Start upはサウンドドライバにGoをかけるだけで、サウンドドライバの転送はSndSimulator起動時に行われます。

  • SndSim2.0以降はDriverの1.29i以降でのみ動作します。それ以前のサウンドドライバの使用はできません。

  • Sound Box(Sound Board System)の4組のLED(32K, 44.1K, 48K, PARITY, DE-EMPの表示）はどんな点灯状態でもサウンドツールの動作には影響ありません。32K, 44.1K, 48Kについては、サウンドボックスのオプティカル入力のサンプリングレイトに対応して点灯するものです。44.1kHz以外の入力は可能ですが動作は保証されませんので止めてください。

  • Sound Box(Sound Board System)背面のＬＥＤ仕様
    ブートＲＯＭ起動時にはＬＥＤ１から８に向かって光りながら移動点滅します。ＳＣＳＩを用いてデータを転送する期間、この動作が一瞬停止しますが転送終了後復活します。
    ターゲットにドライバを転送後、プログラムを実行させるとＬＥＤ１が点滅し、ＣＰＵが正常に動作していることを確認できます。

    ＬＥＤ１が点滅（ＣＰＵが正常に動作）している時における他のＬＥＤの点滅の意味を以下の通り。

    ＬＥＤ２：ＣＰＵ処理能力ＭＡＸ
    ＬＥＤ３：ＢＧＭ解凍の割込み駆動中（通常点滅）。
    ＬＥＤ４：no care
    ＬＥＤ５：no care
    ＬＥＤ６：no care
    ＬＥＤ７：ボード上のＭＩＤＩ-ＩＮ２からのＭＩＤＩ入力。
    ＬＥＤ８：ボード上のＭＩＤＩ-ＩＮ１からのＭＩＤＩ入力。

    またＬＥＤ１が消灯している時の他のＬＥＤの点滅は以下のようなエラーを意味します（点灯したままの場合はSCSI通信中かドライバがHALTした状態です）。

    ＬＥＤ番号
    １２３４５６７８    		意　味
    YM3802(MIDI-1) IRQ vector error
    // (MIDI-2) //
    MIDI data error
    YM3802(MIDI-1) MIDI out error
    // (MIDI-2) //
    MIDI Control change $60〜$7F input
    HOST I/F Commnd execute error
    ...........
    ...........
    Map change error
    BANK change error
    MIXER change error
    EFFECT change error
    68k un-deffinition vector event
    ...........
    68k buss error
    68k address error
    ...........
    68k level-3 event
    68k level-4 event
    68k level-7 event

  • 16Bit、クロック11.3MHzの68EC000がサウンド制御専用CPUとしてSCSPをコントロールします。68EC000はSCSPとダイレクトに接続していて、SH2とは独立して動作します。また、SH2からもSCSPにアクセス可能です。アクセス時にSCSPも68000も停止することはありませんが、時分割処理のためSH2からのアクセス量が多いと68000の処理能力が低下します。

  • SCSPチップのクロックは22.58MHz、68000のクロックは11.3MHz。
    またサウンドドライバのＣＰＵ実行単位時間については、

    ソフトウェア ＤＳＰ制御の実行単位時間は８msec。
    ソフトウェア ＰＬＦＯ の実行単位時間は４msec。
    その他のターゲットプログラムの実行単位時間は２msecです。

  • PCMデータサイズまめ知識
    16bit44.1kHzで1秒88kbyte（サウンドRAMのほぼ最大である450kbyteで約5秒）。
    8bit11kHzで1秒11kbyte（サウンドRAMのほぼ最大である450kbyteで約40秒）。
    SCSPにおいて1波形は最大64ksampleまでですので、16bit8bitとも、44.1kHzで0.72秒、11kHzで2.9秒。
