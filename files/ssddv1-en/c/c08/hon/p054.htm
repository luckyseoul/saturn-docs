7.5 Checkpoint 

 symptom 
 cause 
 No sound 
 □ Is the sound driver working? 
 If you are not sure, try issuing some sound control commands 
. If the issued command code is cleared to 00h, the driver is operating 
. 
 Also, when the sound driver is running, address 8827h: byte 
 (SH address 25A08827h) of the sound memory is incremented every 2msec 
, please check here. 
 
 □ Has sound data been transferred? 
 In order to perform sequence playback, timbre data and sequence data must be correctly transferred to the sound memory. 
 
 □ Is the transferred bit set? 
 After the sound data is transferred, the sound is not played unless the "L" bit (transferred) of the sound area map CRNT work is set. 
 
 □ Are the area map and transfer data match? 
 If the transferred sound data and the area map content are not correct, it may not be pronounced. Check map and data integrity, forwarding address, size 
. 
 
 □ Is the version of the sound driver different? 
 If the driver that created the sound is different from the driver installed in the game, it may not sound correctly. Also, there is a difference in the compression format of the 
 sequence between the old version and the new version. Please check the correct version 
. 
 
 □ Is the sound driver data file damaged? 
 When transferring the sound driver (SDDRVS.TSK) via a Unix server on the network 
 When the line feed code is converted to 
 when the sender is a Macintosh file with the TEXT attribute there is. Before transferring, check that the attribute of the Macintosh file is not TEXT.
