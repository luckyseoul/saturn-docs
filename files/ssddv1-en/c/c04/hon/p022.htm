4.3 Peripheral control

Peripheral control needs to be created in line with game creation standards. The library is intelligently created to make this easy.

4.3.1 Policy

Peripheral acquisition processing is created according to the following policy for flexible response to users.
  • Support as much as possible for future peripherals.
  • Make the system not aware of multi-tap.
  • Take measures against trouble.

4.3.2 Method

(1) Overview

  • By specifying the required number of peripherals, the peripheral ID to be acquired and the peripheral size as input, each peripheral ID and peripheral data are acquired.
    Even if the
  • peripheral acquisition ID is different from the connected peripheral ID, data is acquired if it is connected. For example, get analog device data as mouse data.

(Example)
Input
Required peripherals = 3
Peripheral ID = Digital device
Peripheral size = Digital device size

Connection status
Main unit connector 1 = Multi-tap 6P
Multi-tap connector 1 = Digital device
Multi-tap connector 3 = Analog device
Main unit connector 2 = Keyboard device
(Peripherals not connected other than above)
